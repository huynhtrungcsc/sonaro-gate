# Sonaro Gate • 2025.1 LTS

**Next-Generation Firewall Management Console** — Self-hosted on Ubuntu 24.04 LTS.

```
┌──────────────────────────────────────────────────────────────────┐
│                    SONARO GATE • 2025.1 LTS                      │
│            Next-Generation Firewall Management Console           │
│                                                                  │
│   Internet ──► WAN (eth0) ──► [ SONARO GATE ] ──► LAN (eth1)   │
│                                     │                            │
│                              iptables + NAT                      │
│                              + IPS (Suricata)                    │
│                              + VPN (WireGuard / OpenVPN)         │
│                              + DNS + DHCP                        │
│                              + Web Console :5000                 │
└──────────────────────────────────────────────────────────────────┘
```

Sonaro Gate turns any Ubuntu 24.04 LTS server (or bare-metal PC with two network cards) into a fully functional firewall appliance. All firewall rules, NAT, routing, and IPS settings you configure in the web UI are applied directly to the Linux kernel — no simulation, no demo data.

### Minimum (bare-metal or VM)

| Component | Requirement |
|---|---|
| Operating System | **Ubuntu 24.04 LTS** (Noble Numbat) — 64-bit |
| CPU | 2 cores, x86_64 or ARM64 |
| RAM | 2 GB |
| Disk | 20 GB |
| Network cards | **At least 2 NICs** — one for WAN (internet), one for LAN |
| Privileges | `root` — required for `iptables`, `ip`, `sysctl` |
| Node.js | 20.x LTS (installed automatically by the setup script) |
| PostgreSQL | 16.x (installed automatically by the setup script) |

### Recommended for Production

| Component | Recommendation |
|---|---|
| CPU | 4+ cores |
| RAM | 4–8 GB |
| Disk | 40+ GB SSD |
| NICs | 4 (WAN + LAN + DMZ + Management) |

> **What is a NIC?** A NIC (Network Interface Card) is a network adapter — the port where you plug in a network cable (or Wi-Fi adapter). Most desktop PCs have one. For Sonaro Gate to work as a firewall, you need at least two: one connected to your router/ISP (WAN) and one connected to your internal network (LAN).

## 3. Architecture

Sonaro Gate is a three-layer system:

```
┌─────────────────────────────────────────────────────────────────┐
│  LAYER 1 — Frontend (React + TypeScript)                        │
│                                                                 │
│  Browser on admin's PC/phone                                    │
│  ├── React SPA with 43 management pages                         │
│  ├── TanStack Query — data fetching + caching                   │
│  ├── WebSocket client — receives live metrics every 30s         │
│  └── Talks to backend via HTTP API + WebSocket on port 5000     │
└─────────────────────────┬───────────────────────────────────────┘
                          │ HTTP (JSON) + WebSocket
                          ▼
┌─────────────────────────────────────────────────────────────────┐
│  LAYER 2 — Backend (Express.js + Node.js)                       │
│                                                                 │
│  ├── Auth: JWT token issued at login (bcrypt password check)    │
│  ├── CRUD API: PostgREST-style routes for 30+ DB tables         │
│  ├── System API: talks to OS tools (iptables, ip, sysctl)       │
│  ├── Suricata API: controls IPS engine and custom rules         │
│  ├── Agent: collects CPU/RAM/disk metrics every 30 seconds      │
│  ├── WebSocket server: pushes metrics to connected browsers     │
│  └── Vite dev middleware (development only)                     │
└──────────────┬─────────────────────┬───────────────────────────┘
               │ SQL (Drizzle ORM)   │ Shell commands (exec)
               ▼                     ▼
┌──────────────────┐   ┌─────────────────────────────────────────┐
│  LAYER 3a — DB   │   │  LAYER 3b — Ubuntu Kernel               │
│  PostgreSQL 16   │   │                                         │
│                  │   │  iptables — firewall rules + NAT        │
│  Stores all      │   │  ip addr/route — interface + routing    │
│  configuration:  │   │  sysctl — IP forwarding, kernel params  │
│  • Firewall rules│   │  netplan — persistent network config    │
│  • NAT rules     │   │  suricata — IPS engine + rules          │
│  • VPN tunnels   │   │  wireguard — VPN tunnels                │
│  • Interfaces    │   │  systemctl — service management         │
│  • Certificates  │   │                                         │
│  • Audit logs    │   └─────────────────────────────────────────┘
│  • System metrics│
└──────────────────┘
```

### Key Design Decisions

- **Single port (5000)**: The Express backend serves both the API and the React frontend on port 5000. In development, it proxies to Vite. In production, it serves the built static files.
- **PostgreSQL as source of truth**: All firewall rules live in the database. When you click "Apply", the backend reads the DB and translates rules into real `iptables` commands.
- **Graceful degradation**: If not running as root (e.g., during development), all kernel commands are skipped silently. The UI still works fully.
- **WebSocket + polling hybrid**: Live metrics come via WebSocket. If WebSocket disconnects, the app falls back to HTTP polling every 2 minutes as a safety net.

## 4. System Flow (How Everything Works)

### 4.1 Boot Sequence

```
sudo npx tsx server/index.ts
         │
         ├─► Load .env (DATABASE_URL, JWT_SECRET, PORT)
         │
         ├─► Connect to PostgreSQL
         │      └─► Run Drizzle ORM schema push (auto-migrate)
         │
         ├─► Seed database (if first boot)
         │      └─► Create admin user: admin@sonaro.local / Admin123!
         │          Create default system settings (hostname, serial)
         │
         ├─► Check if setup wizard needed
         │      ├─► Needs root + TTY + setup_complete=false in DB
         │      └─► If yes: run interactive CLI wizard (asks WAN/LAN config)
         │
         ├─► Start background agent (every 30 seconds)
         │      ├─► Read CPU usage from systeminformation
         │      ├─► Read RAM usage
         │      ├─► Read disk usage
         │      ├─► Read NIC bytes in/out from /sys/class/net
         │      ├─► Save to system_metrics and traffic_stats tables
         │      └─► Broadcast to all connected WebSocket clients
         │
         ├─► Attach WebSocket server (noServer mode, path: /ws)
         │      └─► Shares port 5000 with HTTP, no conflict
         │
         ├─► Register API routes
         │      ├─► POST /api/rpc/authenticate
         │      ├─► GET|POST|PATCH|DELETE /api/<table> (all 30+ tables)
         │      ├─► GET|POST /api/system/* (iptables, interfaces, netplan)
         │      └─► GET|POST /api/system/ips/* (Suricata IPS)
         │
         └─► Start HTTP server on port 5000
                └─► Serve React frontend (Vite dev or built static files)
```

### 4.2 Login Flow

```
Browser                    Express Server              PostgreSQL
   │                            │                           │
   │── POST /api/rpc/authenticate ──────────────────────────►│
   │   { p_email, p_password }  │                           │
   │                            │── SELECT user WHERE ───────►│
   │                            │   email = p_email          │
   │                            │◄── user row ───────────────│
   │                            │                           │
   │                            │ bcrypt.compare(password, hash)
   │                            │                           │
   │◄── { token: "eyJ..." } ────│                           │
   │                            │                           │
   │ Store token in             │                           │
   │ localStorage / memory      │                           │
   │                            │                           │
   │── GET /api/firewall_rules ─►                           │
   │   Authorization: Bearer eyJ...                         │
   │                            │ Verify JWT signature      │
   │                            │── SELECT * FROM ───────────►│
   │                            │   firewall_rules           │
   │◄── [ { id, action, ... } ]─│                           │
```

### 4.3 Firewall Rule Enforcement Flow

```
Admin clicks "Apply Config" in web UI
         │
         ▼
POST /api/system/apply-config
         │
         ▼
server/iptables.ts — applyFirewallRules()
         │
         ├─► SELECT * FROM firewall_rules WHERE enabled = true
         │
         ├─► iptables -F FORWARD          (flush old rules)
         │
         ├─► For each rule:
         │    ├─► action=pass    → iptables -A FORWARD -j ACCEPT ...
         │    ├─► action=deny    → iptables -A FORWARD -j DROP ...
         │    └─► action=reject  → iptables -A FORWARD -j REJECT ...
         │
         ├─► SELECT * FROM nat_rules WHERE enabled = true
         │
         ├─► For each NAT rule:
         │    ├─► masquerade → iptables -t nat -A POSTROUTING -j MASQUERADE
         │    └─► dnat       → iptables -t nat -A PREROUTING -j DNAT ...
         │
         └─► netfilter-persistent save   (persist across reboot)
```

### 4.4 Real-Time Dashboard Flow

```
Server (every 30 seconds)             Browser
         │                                │
         │  collect CPU, RAM, disk,       │
         │  NIC stats from OS             │
         │                                │
         ├─► Save to DB                   │
         │                                │
         └─► WebSocket broadcast ─────────►│
             { type: "metrics",            │  useRealtimeMetrics hook
               cpu: 23,                   │  receives data and updates
               ram: 67,                   │  React state immediately
               ... }                      │
                                          │
                                    Dashboard re-renders
                                    with live values
                                          │
                              (If WebSocket disconnects)
                                          │
                              Fallback: HTTP poll every 2 min
                              GET /api/system/metrics
```

### 4.5 IPS (Suricata) Flow

```
Admin clicks "+ Add Custom Rule" in IPS page
         │
         ▼
POST /api/system/ips/rules
{ sid: 9001234, action: "drop", protocol: "tcp",
  srcIp: "any", dstIp: "any", dstPort: "4444",
  message: "Block suspicious C2 traffic" }
         │
         ▼
server/suricata.ts — addLocalRule()
         │
         ├─► Read /etc/suricata/rules/sonaro-local.rules
         │
         ├─► Check: is SID already used? (prevent duplicates)
         │
         ├─► Append new rule:
         │    drop tcp any any -> any 4444
         │    (msg:"Block suspicious C2 traffic";
         │     sid:9001234; rev:1;)
         │
         ├─► Write file back
         │
         └─► kill -USR2 $(pidof suricata)
              │
              └─► Suricata hot-reloads rules without restarting
                  New rule is now ACTIVE in the kernel
```

## 5. Deploy on Ubuntu 24.04 LTS — Step by Step

> **Reading this for the first time on Linux?** Follow every command exactly. Lines starting with `#` are comments — do not type them. Lines starting with `$` mean run as a regular user. Lines starting with `#` (in a terminal) mean run as root.

### Step 1 — Prepare the server

You need a machine running **Ubuntu 24.04 LTS** with at least two network cards. This can be:
- A physical PC or server
- A virtual machine (VMware, VirtualBox, Proxmox, KVM)
- A cloud VPS (note: cloud VMs usually have one NIC — you'd need to add a second)

First, open a terminal and check that you have Ubuntu 24.04:

```bash
cat /etc/os-release
# You should see: VERSION="24.04 LTS (Noble Numbat)"
```

Check that you have at least 2 network interfaces:

```bash
ip link show
# You should see at least: lo, eth0 (or ens3), eth1 (or ens4)
# lo is the loopback interface — does NOT count as a real NIC
```

### Step 2 — Install Git and download Sonaro Gate

```bash
# Update package list first (always do this before installing anything)
sudo apt-get update

# Install Git (to download the code)
sudo apt-get install -y git

# Download Sonaro Gate source code
git clone https://github.com/huynhtrungcsc/sonaro-gate.git /opt/sonaro-src

# Go into the downloaded folder
cd /opt/sonaro-src
```

### Step 3 — Run the automated installer (recommended)

The installer script does everything automatically: installs Node.js, PostgreSQL, Suricata, WireGuard, OpenVPN, dnsmasq, configures the database, creates a systemd service, and starts everything.

```bash
# Run the installer as root (sudo gives root access)
sudo bash scripts/setup-ubuntu.sh
```

**What this script does, step by step:**

1. Runs `apt-get update` — refreshes the list of available packages
2. Installs system packages: `iptables`, `iptables-persistent`, `iproute2`, `openssl`, `postgresql`, `jq`, `curl`, `netplan.io`
3. Installs Node.js 20.x (downloads from the official NodeSource repository)
4. Installs Suricata IPS + suricata-update (downloads Emerging Threats rule sets)
5. Installs WireGuard VPN + generates server keys
6. Installs OpenVPN + creates PKI (certificate authority, server certificate, Diffie-Hellman params)
7. Installs dnsmasq (DHCP/DNS server)
8. Enables IP forwarding in the kernel (`net.ipv4.ip_forward = 1`)
9. Configures `iptables-persistent` so firewall rules survive reboots
10. Creates the PostgreSQL database and user with a random strong password
11. Runs Drizzle ORM migrations (creates all database tables)
12. Creates `/etc/systemd/system/sonaro-gate.service`
13. Enables and starts the service

The installer takes about 5–10 minutes depending on internet speed. When it finishes, you will see:

```
╔══════════════════════════════════════════════════════════╗
║                  SETUP COMPLETE                         ║
╚══════════════════════════════════════════════════════════╝

  Web UI:      http://192.168.1.100:5000
  Admin login: admin@sonaro.local
  Admin pass:  Admin123!
```

### Step 4 — Verify the service is running

```bash
# Check if Sonaro Gate is running
sudo systemctl status sonaro-gate

# You should see "active (running)" in green
# If it shows "failed", check the logs:
sudo journalctl -u sonaro-gate -n 50
```

```bash
# Check if Suricata IPS is running
sudo systemctl status suricata

# Check if PostgreSQL is running
sudo systemctl status postgresql
```

### Step 5 — Access the web interface

Open a browser on any computer connected to the LAN side of your firewall and go to:

```
http://<LAN_IP_OF_SONARO_GATE>:5000
```

Login with:
- Email: `admin@sonaro.local`
- Password: `Admin123!`

> **IMPORTANT**: Change the admin password immediately after your first login. Go to System → Administrators → Edit.

### Step 6 — Run the first-boot wizard (optional, for full network setup)

If you want Sonaro Gate to configure your network interfaces (WAN/LAN IP addresses, routing, NAT) interactively, run:

```bash
# Stop the service first
sudo systemctl stop sonaro-gate

# Run interactively as root (wizard only runs with a terminal)
sudo npx tsx /opt/sonaro/server/index.ts
```

The wizard will ask you:
- Which interface is WAN (connected to internet/router)?
- WAN type: DHCP (automatic) or Static (manual IP)?
- Which interface is LAN (connected to your local network)?
- LAN IP address (default: 192.168.1.1)
- Admin password

After the wizard, restart normally:

```bash
sudo systemctl start sonaro-gate
```

### Step 7 — Manual installation (alternative to the script)

If you prefer to do everything manually, follow these steps:

#### 7a — Install Node.js 20

```bash
# Download the Node.js 20 setup script from NodeSource
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -

# Install Node.js
sudo apt-get install -y nodejs

# Verify installation
node --version   # Should print: v20.x.x
npm --version    # Should print: 10.x.x
```

#### 7b — Install and configure PostgreSQL

```bash
# Install PostgreSQL
sudo apt-get install -y postgresql

# Start and enable PostgreSQL
sudo systemctl enable postgresql
sudo systemctl start postgresql

# Create database user and database
# (The -u postgres runs this command as the postgres system user)
sudo -u postgres psql -c "CREATE USER sonaro WITH PASSWORD 'change_this_password_123';"
sudo -u postgres psql -c "CREATE DATABASE sonaro_gate OWNER sonaro;"

# Verify the database was created
sudo -u postgres psql -l | grep sonaro_gate
```

#### 7c — Clone the application

```bash
# Copy files to the install directory
sudo cp -r /opt/sonaro-src /opt/sonaro
cd /opt/sonaro

# Install Node.js dependencies
sudo npm install
```

#### 7d — Create the environment file

```bash
# Create the .env file with your database credentials
sudo nano /opt/sonaro/.env
```

Paste this content into the file (change the password to match what you set in step 7b):

```
DATABASE_URL=postgresql://sonaro:change_this_password_123@localhost:5432/sonaro_gate
NODE_ENV=production
PORT=5000
ADMIN_EMAIL=admin@sonaro.local
ADMIN_PASSWORD=Admin123!
```

Save and exit: press `Ctrl+X`, then `Y`, then `Enter`.

Set the correct permissions (only root can read this file — it contains your database password):

```bash
sudo chmod 600 /opt/sonaro/.env
```

#### 7e — Build the frontend and set up the database

```bash
cd /opt/sonaro

# Build the React frontend (creates dist/ folder)
sudo npm run build

# Push database schema (creates all tables)
sudo npm run db:push

# Seed default data (admin user, settings)
sudo npx tsx server/seed.ts
```

#### 7f — Install Suricata IPS

```bash
# Install Suricata and the rule updater
sudo apt-get install -y suricata suricata-update

# Create directory for custom rules
sudo mkdir -p /etc/suricata/rules
sudo touch /etc/suricata/rules/sonaro-local.rules

# Download Emerging Threats rule sets (requires internet)
sudo suricata-update

# Enable and start Suricata
sudo systemctl enable suricata
sudo systemctl start suricata
```

#### 7g — Install WireGuard VPN

```bash
# Install WireGuard
sudo apt-get install -y wireguard wireguard-tools

# Generate server key pair
wg genkey | sudo tee /etc/wireguard/server_private.key | wg pubkey | sudo tee /etc/wireguard/server_public.key
sudo chmod 600 /etc/wireguard/server_private.key

# Your server public key (share this with VPN clients):
cat /etc/wireguard/server_public.key
```

#### 7h — Enable IP forwarding

```bash
# Enable immediately (takes effect now)
sudo sysctl -w net.ipv4.ip_forward=1

# Make it permanent (survives reboots)
echo "net.ipv4.ip_forward=1" | sudo tee /etc/sysctl.d/99-sonaro.conf
echo "net.ipv6.conf.all.forwarding=1" >> /etc/sysctl.d/99-sonaro.conf
```

#### 7i — Install iptables persistence

```bash
# Install the persistence tool
sudo apt-get install -y iptables-persistent

# Add basic NAT rule (replace eth0 with your WAN interface name)
sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

# Save current rules so they survive reboots
sudo netfilter-persistent save
```

#### 7j — Create the systemd service

```bash
# Create the service file
sudo nano /etc/systemd/system/sonaro-gate.service
```

Paste this content:

```ini
[Unit]
Description=Sonaro Gate — Next-Generation Firewall Console
After=network.target postgresql.service
Wants=postgresql.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/sonaro
EnvironmentFile=/opt/sonaro/.env
ExecStart=/usr/bin/node /opt/sonaro/dist/server/index.js
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal
SyslogIdentifier=sonaro-gate

[Install]
WantedBy=multi-user.target
```

Save and exit (`Ctrl+X`, `Y`, `Enter`), then:

```bash
# Tell systemd about the new service file
sudo systemctl daemon-reload

# Enable (start automatically on boot)
sudo systemctl enable sonaro-gate

# Start now
sudo systemctl start sonaro-gate

# Check status
sudo systemctl status sonaro-gate
```

### Useful Commands After Installation

```bash
# View live application logs
sudo journalctl -u sonaro-gate -f

# View IPS alerts in real time
```

```bash
# Pull latest code

```

## 6. Deploy with Docker

> **Important**: For `iptables`, `ip`, and `suricata` to work on the real host network, Docker must run with `--privileged` and `--network host`. These settings mean the container directly controls the host machine's networking — there is no isolation between the container and the host network.

### Using Docker Compose (easiest)

```bash
# Clone the repo
git clone https://github.com/huynhtrungcsc/sonaro-gate.git
cd sonaro-gate

# Copy and edit the environment file
cp .env.example .env
nano .env   # Set your passwords and JWT_SECRET

# Start everything (PostgreSQL + Sonaro Gate)
docker compose up -d

# Watch the logs
docker compose logs -f sonaro-gate
```

Access at: `http://localhost:5000`

### Using Docker directly

```bash
# Build the image
docker build -t sonaro-gate:latest .

# Run with full network access
docker run -d \
  --name sonaro-gate \
  --privileged \
  --network host \
  --env-file .env \
  -v /etc/netplan:/etc/netplan \
  -v /etc/iptables:/etc/iptables \
  -v /etc/suricata:/etc/suricata \
  -v /var/log/suricata:/var/log/suricata \
  sonaro-gate:latest
```

## 9. API Reference

### Authentication

All API endpoints (except `/api/health`) require a valid JWT token. Get one by logging in:

```bash
# Login and save token
TOKEN=$(curl -s -X POST http://localhost:5000/api/rpc/authenticate \
  -H "Content-Type: application/json" \
  -d '{"p_email":"admin@sonaro.local","p_password":"Admin123!"}' \
  | jq -r '.token')

echo "Token: $TOKEN"
```

Use the token in all subsequent requests:

```bash
curl -H "Authorization: Bearer $TOKEN" http://localhost:5000/api/firewall_rules
```

### Core Endpoints


### CRUD Table Endpoints

All configuration tables follow the PostgREST query format:

```bash
# List all firewall rules
curl -H "Authorization: Bearer $TOKEN" \
  http://localhost:5000/api/firewall_rules

# Filter: only enabled rules with action=pass
curl -H "Authorization: Bearer $TOKEN" \
  "http://localhost:5000/api/firewall_rules?enabled=eq.true&action=eq.pass"

# Sort by priority, newest first
curl -H "Authorization: Bearer $TOKEN" \
  "http://localhost:5000/api/firewall_rules?order=priority.asc"

# Create a new firewall rule
curl -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Allow HTTP","action":"pass","protocol":"tcp","dst_port":"80","enabled":true}' \
  http://localhost:5000/api/firewall_rules

# Update a rule
curl -X PATCH -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"enabled":false}' \
  "http://localhost:5000/api/firewall_rules?id=eq.5"

# Delete a rule
curl -X DELETE -H "Authorization: Bearer $TOKEN" \
  "http://localhost:5000/api/firewall_rules?id=eq.5"
```

Available tables: `firewall_rules`, `nat_rules`, `network_interfaces`, `static_routes`, `policy_routes`, `vpn_tunnels`, `ip_pools`, `virtual_ips`, `wildcard_fqdns`, `traffic_shapers`, `traffic_shaping_policies`, `dhcp_servers`, `dhcp_static_mappings`, `dhcp_leases`, `dns_servers`, `dns_records`, `dns_filter_profiles`, `ids_signatures`, `certificates`, `schedules`, `audit_logs`, `system_settings`, `system_metrics`, `traffic_stats`, `users`, `user_roles`

## 12. Security Hardening

### Immediately after installation

```bash
# 1. Change the default admin password
# Go to: Web UI → System → Administrators → Edit admin → Change Password

# 2. Generate a strong JWT_SECRET if you haven't already
sudo bash -c 'echo "JWT_SECRET=$(openssl rand -hex 32)" >> /opt/sonaro/.env'
sudo systemctl restart sonaro-gate

# 3. Restrict who can connect to port 5000 (management port)
# Only allow your admin PC (replace 192.168.1.50 with your IP)
sudo iptables -A INPUT -p tcp --dport 5000 -s 192.168.1.50 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 5000 -j DROP
sudo netfilter-persistent save

# 4. Protect the .env file (contains database password)
sudo chmod 600 /opt/sonaro/.env
sudo chown root:root /opt/sonaro/.env
```

### Set up HTTPS (strongly recommended for production)

Install nginx as a reverse proxy with a self-signed certificate:

```bash
# Install nginx
sudo apt-get install -y nginx

# Create self-signed certificate
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/sonaro.key \
  -out /etc/ssl/certs/sonaro.crt \
  -subj "/CN=sonaro-gate/O=Sonaro Gate/C=VN"

# Configure nginx
sudo nano /etc/nginx/sites-available/sonaro-gate
```

Paste:

```nginx
server {
    listen 443 ssl;
    server_name sonaro-gw-01;

    ssl_certificate /etc/ssl/certs/sonaro.crt;
    ssl_certificate_key /etc/ssl/private/sonaro.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}

server {
    listen 80;
    return 301 https://$host$request_uri;
}
```

```bash
sudo ln -s /etc/nginx/sites-available/sonaro-gate /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl restart nginx
```

## 13. Development Guide

### Running in development mode (Replit or local)

```bash
# Install dependencies
npm install

# Create environment file
cp .env.example .env
# Edit .env and set DATABASE_URL to your PostgreSQL connection string

# Push schema to database
npm run db:push

# Start development server (Express + Vite on port 5000)
npx tsx server/index.ts
```

In development mode:
- The React frontend is served by Vite with hot module replacement (HMR)
- If not running as root, all `iptables`/`ip`/`sysctl` commands are skipped gracefully
- The WebSocket server shares port 5000 with Vite HMR — no conflict

### Code structure for adding a new feature

**1. Add the database table** — edit `shared/schema.ts`:
```typescript
export const myNewTable = pgTable('my_new_table', {
  id: serial('id').primaryKey(),
  name: text('name').notNull(),
  enabled: boolean('enabled').default(true),
});
```

**2. Push the schema** — run `npm run db:push`

**3. Add a DB hook** — edit `src/hooks/useDbData.ts`:
```typescript
export function useMyNewData() {
  return useQuery<MyNewType[]>({ queryKey: ['/api/my_new_table'] });
}
```

**4. Add a CRUD API client** — edit `src/lib/api.ts`:
```typescript
export const myNewApi = createCrud<MyNewInsert>('my_new_table');
```

**5. Add the page** — create `src/pages/MyNewPage.tsx`

**6. Register the route** — edit `src/App.tsx`

**7. Add to sidebar** — edit `src/components/layout/Sidebar.tsx`

### CI/CD Pipeline

- **Push to main**: TypeScript typecheck → Vite build → Docker build → `npm audit`
- **Tag `v*.*.*`**: Multi-platform Docker image built and pushed to GitHub Container Registry + GitHub Release created automatically
